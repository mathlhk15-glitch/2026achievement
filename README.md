# 성취기준에서 탐구로

2022 개정 교육과정의 성취기준을 클릭하면 해당 코드에 연결된 질문과 탐구 예시를 모두 보여주는 웹앱입니다. 성취기준 원문과 교과서 목차는 기존 탐색기에서 가져왔으며, 질문·탐구 예시는 `source-docs/`의 DOCX에서 생성합니다.

## 컴퓨터에서 열기

Windows에서는 **실행.cmd**를 더블클릭합니다. 사용 후 **종료.cmd**로 이 폴더에서 실행한 탐색기 서버를 종료할 수 있습니다. 이 컴퓨터의 Codex에 포함된 Python을 우선 사용합니다. 다른 컴퓨터에는 Python 3.10 이상이 필요합니다. 처음 실행하면 웹 데이터를 자동으로 준비합니다. `dist/index.html`을 직접 더블클릭하면 브라우저가 데이터 읽기를 제한하므로 실행 파일을 사용하세요.

다른 운영체제나 명령으로 실행할 때:

```sh
python scripts/build.py
python scripts/validate.py
python -m http.server 8870 --bind 127.0.0.1 --directory dist
```

브라우저에서 `http://127.0.0.1:8870/`을 엽니다. 외부 서버와 유료 API는 사용하지 않습니다.

## 새 문서를 추가하기

1. 과목별 DOCX를 `source-docs/`에 넣습니다. 하위 폴더도 읽습니다.
2. **자료 갱신.cmd**를 더블클릭합니다.
3. 열려 있는 탐색기를 새로고침합니다.

현재 원본 작업 폴더 바로 아래에 이 프로젝트가 있을 때는, 작업 폴더에 새로 생성된 DOCX도 자료 갱신 과정에서 `source-docs/`로 복사합니다. 작업 폴더의 `추가 탐구/` 폴더도 하위 구조를 유지해 `source-docs/추가 탐구/`로 가져옵니다. 같은 경로와 이름은 최신 파일로 교체합니다. 원본 작업 폴더의 파일은 수정하지 않습니다. 삭제한 자료까지 없애려면 작업 폴더와 `source-docs/` 양쪽에서 해당 DOCX를 제거하세요.

JSON은 자동 생성되는 웹용 데이터입니다. 이전에 따로 만들었던 JSON은 필요하지 않습니다. 다만 **`baseline/` 폴더의 JSON은 기준 자료와 공식 수식 표시 보정 자료**이므로 모두 보관하세요. 기준 자료는 원본 탐색기의 성취기준과 목차 정보이고, `dist/data/`는 매번 다시 생성할 수 있는 결과입니다.

새 DOCX는 `[10공수1-01-01]`처럼 성취기준 코드를 포함한 문단으로 각 묶음을 시작하면 됩니다. 한 표 전체에 코드와 예시가 들어 있는 형식도 지원합니다. 표·문단 순서, 줄바꿈, 가로·세로 병합 정보와 기본·심화 구분을 유지합니다. 글꼴·색·페이지 배치는 웹 화면에 맞게 표시합니다. 문서의 질문이나 계획을 AI로 재작성하지 않습니다. 복잡한 수식 객체는 수식의 텍스트를 표시하며 워드의 수식 조판을 재현하지는 않습니다.

## GitHub에 올리기

1. 새 저장소를 만들고 기본 브랜치를 `main`으로 둡니다.
2. GitHub Desktop으로 **이 프로젝트 폴더의 내용**을 저장소의 최상위에 올립니다. 상위 원본 작업 폴더 전체나 ZIP 파일 자체를 올리는 것이 아닙니다. GitHub Desktop을 쓰면 숨김 폴더 `.github`도 함께 올리기 쉽습니다.
3. 저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
4. **Actions → Build and publish explorer → Run workflow**를 실행합니다. 이후 `main`에 파일을 추가하거나 수정하면 자동 갱신됩니다.
5. Actions의 배포 결과 또는 Settings → Pages에서 사이트 주소를 확인합니다.

워크플로는 `source-docs/`의 DOCX를 읽어 JSON을 생성하고, 검증한 뒤 `dist/`의 웹 파일만 게시합니다. 따라서 GitHub 웹 화면에서 `source-docs/`에 새 DOCX를 올려도 사이트가 자동으로 갱신됩니다. 직접 JSON을 편집할 필요가 없습니다. 공개 저장소에는 원본 DOCX도 포함됩니다. 코드나 문서의 재사용 허용 범위는 소유자가 정하도록 라이선스 파일은 추가하지 않았습니다.

`dist/`는 자동 생성 결과여서 Git에서 제외합니다. `baseline/`, `source-docs/`, `public/`, `scripts/`, `.github/`는 함께 올려야 합니다. 배포 설정은 [GitHub 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)를 따릅니다.

## 자료 연결 원칙

- 성취기준은 원본 탐색기의 코드와 문장을 보존합니다. 수식 문자와 분수식 추출이 깨진 16개 항목은 교육부 고시 제2022-33호 원본 HWP 본문·수식과 대조한 표시용 문장을 별도로 적용합니다. 근거는 `baseline/display-overrides.json`과 화면의 ‘수식 보정 근거’에 있습니다.
- 같은 코드의 서로 다른 문서 예시는 모두 표시합니다. 수정 시각이나 파일명만으로 이전 버전을 버리지 않습니다.
- 문단 글꼴 등의 스타일을 제외한 내용과 표 구성이 완전히 같으면 한 예시에 출처를 함께 표시합니다.
- 문서 앞부분에 교과교사 검토 전 초안으로 명시된 자료는 화면과 복사 내용에도 그 상태를 표시합니다.
- 코드가 같아도 원문 문장이 일치하지 않으면 ‘자료 확인 필요’를 표시합니다. 문서 내용을 임의로 고치지 않습니다.
- 탐색기에 없는 코드는 ‘자료 현황 → 연결되지 않은 예시’에서 원문과 함께 볼 수 있습니다.
- 문서를 읽는 중 변경되거나 손상된 파일, 미지원 본문 구조를 만나면 갱신을 중지합니다. 별도 후보 폴더에서 실제 웹 본문·출처까지 대조한 뒤 기존 결과에 반영합니다.
- 연결 보고서는 `reports/import-report.json`과 웹앱의 ‘자료 현황’에서 확인할 수 있습니다.

## 폴더 구성

| 폴더 | 역할 |
| --- | --- |
| `source-docs/` | 원본 DOCX, 새 자료를 넣는 곳 |
| `baseline/` | 원본 탐색기에서 추출한 성취기준과 목차 정보 |
| `public/` | 화면, 동작, 목차 이미지 |
| `scripts/` | 자료 추출, 원문 대조 검증, 로컬 실행 |
| `dist/` | 생성된 웹앱, 이 폴더만 웹에 게시 |
| `reports/` | 파일별 연결·미연결·문장 차이 보고서 |
| `.github/workflows/` | DOCX 변환·검증·GitHub Pages 배포 자동화 |

기준 탐색기를 새 버전으로 교체할 때만 아래 명령으로 기준 자료를 다시 추출합니다.

```sh
python scripts/build.py --baseline "원본탐색기.html"
```

표시 내용은 제공 문서 기준이며 공식 교육과정 원문과 전수 대조했다는 뜻은 아닙니다. 질문과 활동의 적절성은 수업 맥락에서 검토해 사용하세요.

## 업로드 전 검수

최신 수정·검수 결과는 `수정내역_v2.md`를 참고하세요. `업로드전검수.md`와 `검증결과.md`는 이전 판(문서 503개 기준)의 기록입니다. `public/index.html`이 원본 화면 파일이며, ZIP에 `dist/`를 넣지 않은 것은 정상입니다. GitHub Actions가 변환·검사 후 `dist/index.html`을 생성해 게시합니다. 원격 배포의 최종 성공 여부는 저장소를 만든 뒤 Actions 실행 결과로 확인해야 합니다.

문장 차이 검토 목록은 `python scripts/review_list.py`로 `reports/문장차이_검토목록.csv`에 만들 수 있습니다(엑셀에서 바로 열림). 개발 검사는 `python scripts/test_importer.py`, `python scripts/test_server.py`, `node scripts/test_frontend.cjs`입니다. 일반 실행과 자료 갱신에는 Python만 필요합니다. 검사한 소스를 다시 묶을 때는 `python scripts/package.py`를 실행합니다.
